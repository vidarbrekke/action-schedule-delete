# Tune Tussle: App Idea Refinement, Business Requirements & Spec

## 1. Overview

Tune Tussle is a real-time multiplayer music quiz game where players compete to identify song snippets generated by an AI based on user prompts. The app is designed as a mobile-first/mobile-optimized web app (PWA), playable on both mobile devices and computers.

---

## 2. MVP Scope (Phase 1)

### 2.1. Core Principles
- **Local Play Only:** The Judge plays audio on their device; no remote audio sync.
- **No User Accounts:** All gameplay is session-based; no login or persistent user data.
- **No Monetization:** No ads, purchases, or premium features in MVP.
- **LLM Integration:** Use OpenRouter.ai with a admin selected LLM for song selection (configurable model, starting with free models; admin UI for model selection).
- **Design:** Playful but clean UI/UX.
- **Accessibility:** Not required for MVP.
- **Multi-language Support:** Plan for early, but MVP may launch in a single language with i18n-ready codebase.
- **Data Privacy:** No special requirements for MVP.

### 2.2. MVP Features
- **Game Creation (Judge):**
    - Start a new game.
    - Choose "Local Play" mode.
    - Set number of rounds (e.g., 10 songs).
    - Enter a prompt for the AI (e.g., "90s hip hop").
    - Receive a unique game code to share with participants.
    - See a list of participants in the lobby.
    - Start the game when all are ready.
    - Initiate playback of each song snippet (Judge manually plays audio from YouTube or similar).
    - Manual override/correction of scoring for a round.
    - End the game at any time.

- **AI Song Selection:**
    - When the Judge provides a prompt, the system uses the selected LLM (via OpenRouter.ai) to generate a list of N relevant songs (title and artist).
    - For each song, the system identifies a corresponding YouTube (or other source) audio track (link only; playback is manual and triggered by admin).
    - Define a 5-10 second snippet to be played (initially, just the first 5-10 seconds).

- **Game Participation (Participant):**
    - Join a game using a code.
    - See when the game/round starts.
    - Hear the song snippet from the Judge's device (no remote sync).
    - Prominent "BUZZ IN" button.
    - When first to buzz in, answer input is activated.
    - Submit guessed song title and/or artist.
    - If answer is wrong or time runs out, buzzers re-open for others.

- **Gameplay Logic & Scoring:**
    - Only the first participant to buzz in can answer.
    - Time limit for answering after buzzing in.
    - Automated answer verification (LLM and/or fuzzy match against correct title/artist).
    - Points awarded for correct song (+X), artist (+Y), both (+bonus Z).
    - Optional: Subtract points for incorrect answer.
    - After incorrect answer/timeout, allow others to buzz in.
    - After correct guess or all fail, display correct answer to all.
    - Real-time leaderboard.
    - Declare winner at end of N rounds.

- **Technical Stack:**
    - **Frontend:** React (TypeScript), PWA, Tailwind CSS, i18n-ready.
    - **Backend:** Node.js (TypeScript), Express or Fastify, Socket.IO for real-time.
    - **Database:** Minimal (session/game state only; no user accounts).
    - **LLM:** OpenRouter.ai (configurable model).
    - **Music Source:** YouTube Data API for search/links (manual playback).

## 3. Future Features (Phase 2+)

### 3.1. Remote Play
- Synchronized audio playback on all participant devices (Web Audio API, server timestamps, buffering).
- Latency compensation and fairness logic.
- Audio snippet selection (dynamic/randomized segments).

### 3.2. User Accounts & Stats
- Optional login (email/social).
- Persistent user stats, profiles, and friend lists.
- Game history and achievements.

### 3.3. Monetization
- Cosmetic purchases (themes, buzzer sounds, avatars).
- Ad-supported free tier and premium upgrades.
- Premium game modes/song packs.
- "Host Pro" subscription for advanced features.

### 3.4. Enhanced Gameplay
- Power-ups/lifelines (hints, 50/50, steal, etc.).
- Streak bonuses and advanced scoring.
- Themed game packs and curated playlists.
- Spectator mode and chat.
- Daily/weekly challenges and leaderboards.
- Custom game packs (user-generated content).

### 3.5. Accessibility & Internationalization
- Full accessibility support (screen readers, keyboard navigation, color contrast).
- Multi-language UI and content.

### 3.6. Data Privacy & Compliance
- GDPR and other data privacy compliance as needed.
- User data export/deletion features.

## 4. Technical Stack Considerations (Expanded)

- **Frontend:**
    - React (TypeScript), PWA, Tailwind CSS, i18n-ready
    - Responsive/mobile-first design
    - Service worker for offline support
- **Backend:**
    - Node.js (TypeScript), Express/Fastify
    - Socket.IO for real-time events
    - REST endpoints for game/session management
- **Database:**
    - PostgreSQL or Firebase (for rapid prototyping)
    - Minimal schema for MVP; expand for accounts/stats in future
- **LLM Integration:**
    - OpenRouter.ai (configurable model)
    - Admin UI for model selection
- **Music Source:**
    - YouTube Data API for search/links
    - Explore licensed snippet APIs for future
- **Testing:**
    - Unit/integration tests for backend
    - E2E tests for frontend (Cypress/Playwright)
- **Deployment:**
    - Vercel/Netlify for frontend
    - Railway/Render/Fly.io for backend
    - CI/CD for auto-deploys
